# HeliosCLI Session UX Research Spec

## Problem
Session management UI is clunky at scale; users need fast scope filtering and semantic search into past chats.

## Target Features
1. `Shift+Tab` scope cycle in resume picker:
- `Project` (cwd-filtered)
- `All` (current behavior for `--all`)
- `Favorites` (starred sessions)

2. In-chat search modes:
- `Title only` (existing `search_term` path)
- `BM25 turns` (default deep-search mode)
- `RAG turns` (optional precision mode)

3. Cheap-model summarization/labeling:
- Background job labels sessions (`bugfix`, `incident`, `research`, `stalled`, `handoff-needed`).
- Use cheapest available model tier and budget limits.

## Existing Surfaces
- Protocol filter object: `codex-rs/app-server-protocol/src/protocol/v2.rs`
- Backend list and filters: `codex-rs/app-server/src/codex_message_processor.rs`
- Picker UI logic: `codex-rs/tui/src/resume_picker.rs`

## Proposed Interface Additions
- Extend thread list params with `scope_mode` and `search_mode`.
- Add favorites store in `codex_home`.
- Add local BM25 index store over rollout turn text.

## Acceptance Criteria
1. `Shift+Tab` cycles scope modes deterministically.
2. BM25 returns sessions by chat content, not only title.
3. Favorites scope is persisted and queryable.
4. Summarization labels are present on thread rows.
5. Search and scope actions remain performant on 10k+ sessions.

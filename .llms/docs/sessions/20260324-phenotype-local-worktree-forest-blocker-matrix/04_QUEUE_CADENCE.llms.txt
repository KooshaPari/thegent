# 04_QUEUE_CADENCE

Operational convention for turning the blocker matrix into work without duplicating stale numbered lists across files.

## Full-turn delivery (release-grade)

A **full** turn is **not** only verification: **each** turn that touches a product repo should aim for **≥1 merge** to **`main`** or **`release/*`** (or multiple PRs/merges when CI allows), with:

- **`gh` visibility:** `gh pr list` / `gh pr view` / `gh pr checks` for every candidate merge.
- **Changelog:** entries under `## [Unreleased]` (or project equivalent) when the change is user- or policy-visible; see `docs/guides/CHANGELOG_PROCESS.md` in `thegent`.
- **Version / tags:** per repo release policy (semver bump in the same PR as release or a dedicated release PR).
- **Exceptions:** if merge is impossible (red CI, approval, dirty tree), record in `05_KNOWN_ISSUES.md` and link **`FULL_TURN_DELIVERY.md`** snapshot.

**Wave C (`09_NEXT_WAVE_C.md`)** items are written with explicit **Ship** lines so automation can score PR/merge/changelog/version work.

## Per-turn batch size

- Target **24 actionable items** per automation turn.
- Split into **6 slices × 4 items** so each slice maps to one family or comparison slice:
  1. `heliosApp`
  2. `heliosCLI`
  3. `helios-cli` / `colab` / `helMo`
  4. `cliproxy` (including `cliproxy-wtrees` vs `cliproxy-wtress` drift)
  5. `portage` (prune vs decision-gated detached)
  6. `trace` / `trash-cli` / `ralph-codex-loop`

## Carry-forward rules

- If a slice returns fewer than four **new** lanes, fill remaining slots with **explicit carry-forward** blockers (still open from the prior wave), not silent repeats.
- **Clean lanes** called out in `01_RESEARCH.md` stay out of the active queue unless their status changes.
- **Locked** lanes (`trace` initializing locks, **unborn** `ralph-codex-loop`) stay in the blocker class until the underlying git state changes; they may appear as carry-forwards across turns.

## Documentation hygiene

- **Family facts** (dirty counts, lane names, detached vs prunable) belong in `01_RESEARCH.md` and `05_KNOWN_ISSUES.md`.
- **Volatile numbered “next 24” lists** should not be copied into multiple session files each turn; update research/issues when facts change, and treat per-turn queues as ephemeral automation output unless promoted into research after verification.

## Verification commands (quick)

Run from a lane path before claiming it clean or prunable:

```
git status --short
git worktree list --porcelain
```

For unmerged or odd index states:

```
git ls-files -u -- path/to/file
```

# Rust Workflow + Productivity CLI Utilities (libs.tech)

## Scope and timing

This report summarizes **workflow/productivity-oriented Rust CLI utilities** appearing in the `Rust → CLI Libraries` stream on libs.tech, with examples relevant to terminal-first workflows. Snapshot context is aligned to the 2026 listing pages.

Primary source crates included below:

## 1) pueue — task queue for long-running shell jobs

- **libs.tech position**: CLI Libraries (listed in the `New Rust CLI Libraries 2026` feed)
- **Primary use**: Keep long/parallel shell tasks running outside one terminal session and monitor them from another.

### Usage patterns

- Start daemon (first-time/service behavior):
  - `pueued` (daemon process)
  - `pueued -d` (daemon mode in some setups)
- Add jobs:
  - `pueue add "sleep 120"`
  - `pueue add -- ls -la /tmp`
- Check status:
  - `pueue status`
  - `pueue log <task-id>`
  - `pueue follow <task-id>`
- Control execution:
  - `pueue pause`, `pueue start`, `pueue kill <task-id>`, `pueue restart <task-id>`
- Maintain queues:
  - `pueue group`, `pueue stash`, `pueue enqueue`, `pueue clean`, `pueue remove <task-id>`

### Value

- Preserves work state across SSH disconnections by persisting queued/running jobs via background daemon.
- Useful for batch scripts, local build/test orchestration, and one-shell multitasking.
- Queue + group model simplifies ad hoc prioritization and concurrency control from the CLI.

### Limitations

- More interactive than script-centric; not built as a full programmable scheduler/executor.
- Requires daemon lifecycle planning (installing service, socket location, and permissions).
- Command arguments need careful shell escaping (commands are executed by shell).

## 2) xh — fast HTTP API client

- **libs.tech position**: CLI Libraries and HTTP Clients
- **Primary use**: Human-friendly REST API testing and rapid endpoint debugging from terminal.

### Usage patterns

- Basic request:
  - `xh GET https://api.example.com/health`
  - `xh POST https://api.example.com/items name=alice`
- JSON/form modes:
  - `xh --json` (default for structured body)
  - `xh --form` for form-style payloads
- Header/body/query helper syntax:
  - `Authorization:Bearer...`
  - `name=value` (string field)
  - `age:=30` (numeric JSON type)
  - `q==searchTerm` (query parameter syntax)
- File upload:
  - `xh POST http://example.com/upload file@path/to/file.bin`

### Value

- Faster and friendlier replacement for repetitive `curl` commands.
- Supports multiple output formats and concise data shaping for API debugging.
- Good for quick smoke checks against microservices and local endpoints.

### Limitations

- Not intended to replace full API test frameworks with assertions/reporting.
- Shell-friendly JSON/request syntax has a learning curve; complex payloads can become hard to read in long one-liners.

## 3) dust — intuitive `du` replacement

- **libs.tech position**: CLI Libraries
- **Primary use**: Disk usage exploration when the default `du` output is hard to scan.

### Usage patterns

- Basic runs:
  - `dust`
  - `dust /path`
- Focus depth and scope:
  - `dust -d 3`
  - `dust -D` (directories only)
  - `dust -F` (files only)
- Sorting and filtering:
  - `dust -n 30` (top N)
  - `dust -p` (full path), `-r` (reverse), `-z 20MB` (minimum size)
  - include/exclude by regex: `-e '\.png$'`, `-v '\.log$'`
- Size mode:
  - `-o si|kb|mb` etc
- Alternate output:
  - `dust --json` and config file in `~/.config/dust/config.toml`

### Value

- Excellent for first-pass cleanup triage and identifying large directories quickly.
- Visual, sorted output is easy to interpret versus plain numeric `du` listing.
- Fast for exploratory local filesystem analysis.

### Limitations

- Snap-based install channels can limit filesystem visibility.
- Apparent size behavior differs from some tools when hard links are involved.
- Not a replacement for full storage/audit tooling (reporting, retention policy enforcement).

## 4) jnv — interactive JSON navigator + jq helper

- **libs.tech position**: CLI Libraries and JSON Libraries
- **Primary use**: Explore and filter JSON interactively with immediate feedback.

### Usage patterns

- Read JSON file or stdin:
  - `jnv data.json`
  - `cat data.json | jnv`
- Interactive workflow:
  - Use left pane for structured navigation, right pane for editable filter
  - Works with JSON Lines or stream-parseable multi-object JSON input
- Tuning and customization:
  - config file via TOML (`~/.config/jnv/config.toml` or platform equivalent)
  - reactivity, theme, completion, and keybindings are configurable

### Value

- Combines quick visual inspection and `jq` filtering without separate tooling.
- Faster iteration on data exploration and debugging API payloads.
- Reduces context switching when investigating logs/API output.

### Limitations

- Interactive UX is less suited for fully automated non-interactive scripts.
- Filter auto-completion is currently limited to specific jq expression classes.
- Best value with JSON-like terminal flows; binary streams or non-JSON formats require conversion first.

## 5) skim — fuzzy finder for interactive terminal workflows

- **libs.tech position**: Rust CLI Libraries
- **Primary use**: Fuzzy select items (files, history, command output) and pipe results into shell actions.

### Usage patterns

- Direct filtering mode:
  - `sk`
  - `find . -name '*.rs' | sk`
- Multi-select for batch actions:
  - `vim $(find . -name '*.rs' | sk -m)`
- Interactive command mode:
  - `sk --ansi -i -c 'rg --color=always --line-number "{}"'`
- Shell integration:
  - Key bindings for `ctrl-r`/`ctrl-t` style history/file pickers via provided shell scripts

### Value

- Strong productivity gains for navigation-heavy workflows.
- Integrates well with `rg`, `git`, and editor workflows.
- Keeps command discovery and execution in one terminal interaction loop.

### Limitations

- Interactive interface adds overhead for simple scripted filtering.
- Best-effort `SKIM_DEFAULT_COMMAND` tuning needed for large repos to avoid long startup latency.

## 6) atuin — shell history and searchable command memory

- **libs.tech position**: Rust CLI Libraries and Productivity category
- **Primary use**: Replace plain shell history with searchable, contextual, optionally synced command history.

### Usage patterns

- Setup flow:
  - `bash <(curl ... setup.atuin.sh)`
  - `atuin import auto`
- Daily operation:
  - `ctrl-r` / `Up` for context-aware search UI
  - `atuin search <query>`
  - `atuin sync` (manual trigger), automatic sync when enabled
  - `atuin stats` for local usage analysis

### Value

- Speeds recall for forgotten commands and recurring workflows.
- Supports multi-machine continuity when sync is enabled.
- Stores richer metadata than default shell history (duration, exit code, context).

### Limitations

- Sync/encrypted account setup has extra onboarding for users expecting immediate local-only behavior.
- Team/device sync introduces privacy and key-management considerations.
- Heavier than vanilla shell history for minimal setups.

## 7) bandwhich — network utilization triage utility

- **libs.tech position**: Rust CLI Libraries (listed as part of newer CLI stream)
- **Primary use**: Real-time view of bandwidth by process/connection/remote host.

### Usage patterns

- Basic launch:
  - `bandwhich`
- Narrow view:
  - `bandwhich --total-utilization`
  - interface filter: `bandwhich --interface eth0`
  - DNS-only view: `bandwhich --show-dns`
- Requires packet capture permissions on many systems; Linux often uses `setcap` or sudo.

### Value

- Fast visual triage for “which process is using bandwidth?” incidents.
- Helps debug noisy neighbors, stuck builds, or unexpected external traffic.

### Limitations

- Requires elevated privileges for full packet/process mapping on many systems.
- Project is in passive maintenance mode with limited new feature development.
- Best for ad-hoc diagnosis, not long-term network policy monitoring.

## Cross-tool adoption notes

- For **interactive terminal productivity**, `skim` + `jnv` + `atuin` improve retrieval speed and command recall.
- For **ops-heavy execution loops**, `pueue` gives queue continuity while `xh` accelerates API debugging.
- For **local triage** (`space` and `network`), `dust` and `bandwhich` cover two common bottleneck investigations.

Given how quickly this surface evolves, treat this as a rolling shortlist; each utility should be validated against your team’s shell platform and security posture before hard recommendations.

# Proposal: Thegent App Composition V1 Boundary Contract

## Problem Statement

The current application composition boundary is not explicitly codified as a contract artifact.
Without a concrete contract, orchestration responsibilities can drift into domain ownership,
which increases coupling and slows parallel module evolution.

## Change Summary

This change adds a lane-scoped, additive documentation and contract bundle:

1. Rollout docs for app-composition-v1 scope and execution tasks.
2. Contract JSON describing allowed orchestration-layer responsibilities.
3. Explicit disallowed domain ownership that must be delegated to external modules.
4. A validation script that checks artifact presence and required contract keys.

## Goals

- Lock orchestration boundaries at documentation + machine-readable contract layers.
- Prevent the app composition layer from owning domain logic.
- Enable follow-up implementation work to consume a clear migration checklist.

## Non-Goals

- No codebase-wide module refactor in this step.
- No runtime behavior changes in this step.
- No migration execution in this step.

## Acceptance Criteria

- `docs/changes/shared-modules/thegent-app-composition-v1/proposal.md` exists.
- `docs/changes/shared-modules/thegent-app-composition-v1/tasks.md` exists.
- `docs/contracts/thegent-app-composition.contract.json` exists and includes required keys.
- `docs/guides/thegent-app-composition-boundary.md` exists with before/after boundaries and checkpoints.
- `scripts/validate_thegent_app_composition_contract.sh` validates all required artifacts and contract keys.

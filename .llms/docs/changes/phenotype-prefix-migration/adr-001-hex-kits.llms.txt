# ADR-001: Neutral naming for language hexagonal kits

## Status

Proposed

## Context

Historical repos used `phenotype-{go,py,ts,rust}-hexagonal` (or similar) for **generic** clean/hexagonal scaffolding. The taxonomy classifies these as **Tier B**: marketable, not org-semantics.

## Decision

When renaming (GitHub + docs):

1. Use a **consistent pattern** per ecosystem, for example:
   - `go-hexagonal-kit` / `hex-ports-go`
   - `py-hexagonal-kit`
   - `ts-hexagonal-kit`
   - `rust-hexagonal-kit` or `hex-core-rs`
2. Apply **one ADR stack** so all four names feel like one product family.
3. Keep **git history** via GitHub rename (or documented move) rather than copy-paste repos.

## Consequences

- **Positive**: Clearer consumption by non-Phenotype users; aligns with polyrepo productization.
- **Negative**: Every consumer must update `go.mod` / `package.json` / `Cargo.toml` paths; CI secrets and submodule URLs need a checklist.

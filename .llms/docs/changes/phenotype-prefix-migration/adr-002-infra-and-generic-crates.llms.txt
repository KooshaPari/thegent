# ADR-002: Neutral names for infrastructure and generic crates

## Status

Proposed

## Context

Repos such as **`phenotype-infrakit`**, **`phenotype-cipher`**, **`phenotype-sentinel`**, **`phenotype-nexus`**, **`phenotype-patch`**, **`phenotype-vessel`**, **`phenotype-forge`**, **`phenotype-gauge`**, **`phenotype-logger`**, and **`phenotype-metrics`** implement **domain-agnostic** capabilities. Crate names already use neutral words in READMEs (`cipher`, `forge`, …) while the GitHub repo stays `phenotype-*`.

## Decision

1. **Repo rename** to neutral names (examples in inventory) when publishing or promoting externally.
2. **Inner Rust crates**: rename `phenotype-*` crate names to neutral **`snake_case`** names in a **single semver-major** release, with a migration note (avoid silent breakage).
3. **`phenotype-shared`**: remains org **Tier A** as an integrated workspace; extract individual crates to neutral names only via explicit extraction ADRs.

## Redis / cache duplication

If both **`phenotype-shared`** (workspace crate) and a standalone **`phenotype-redis-adapter`** exist, pick **one** canonical implementation and re-export or delete the duplicate in a follow-up PR.

## Consequences

- **Positive**: crates.io and docs match mental model; less “org lock-in” on generic code.
- **Negative**: Coordination cost across consumers; needs release notes and possibly codemods.

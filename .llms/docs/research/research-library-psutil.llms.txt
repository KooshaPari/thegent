# Library Replacement Research — psutil

**WORK_STREAM ID:** `research-library-psutil`
**Priority:** P2
**Status:** ✅ Research complete (no implementation yet)

## Purpose

Evaluate `psutil` for runtime telemetry and process/system-safety usage in thegent orchestration and monitoring paths.

## Findings

- `psutil` covers process CPU, memory, disk, and network metrics with a stable cross-platform API.
- It reduces hand-rolled OS probing and improves portability versus platform-specific shell parsing.
- It is suitable for headless/CI observability where lightweight polling plus budget thresholds are needed.
- Use caution for high-frequency polling frequency and cleanup (avoid unbounded background threads).

## Recommendation

Use `psutil` as a **baseline system telemetry library** where direct process and resource visibility is required (e.g., concurrency cap, runaway cleanup, load-based backoff).

## Next Action

1. Add telemetry helpers around existing governance and autosync loops only after a budgeted poll contract is finalized.
2. Add unit tests for threshold transitions (`warn`, `throttle`, `hard-stop`) and validate in Linux/macOS CI.

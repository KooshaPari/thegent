ARCHITECTURE HIGHLIGHTS:
1. Task Classification (TaskClassifier)
   - Token estimation: word_count_div_1.3 (conservative)
   - Complexity scoring: keywords + tokens + structure (0.0–1.0)
   - Categorization: FAST, NORMAL, COMPLEX, HIGH_COMPLEX
   - Cost/duration estimation per category

2. Constraint Validation (ConstraintValidator)
   - 4 hard constraints checked in isolation
   - Violations returned as list of strings (empty = all pass)
   - Early fail-fast before expensive policy checks

3. Pareto Route Selection (resolve_route_for_category, Phase 2)
   - Quality-focused for COMPLEX/HIGH_COMPLEX tasks
   - Cost-focused for FAST tasks
   - Balanced for NORMAL tasks
   - Quality metadata from model catalog

4. Cost Governance (CostAggregator, Phase 2)
   - Per-category tracking (FAST, NORMAL, COMPLEX, HIGH_COMPLEX)
   - Daily and MTD totals
   - Budget exhaustion detection (block at 100%, warn at 80%)

5. Policy Integration (PolicyEngine, Phase 2)
   - Task-aware rule evaluation
   - Per-category budget enforcement
   - Escalation queue for denied tasks

DATA FLOW (7 steps):
User Command → parse_command → run_impl
  ↓
Create RunMeta + register_start
  ↓
TaskRouter.classify() → TaskMetadata (category, complexity, cost, duration)
  ↓
ConstraintValidator.validate() → list[violations] (empty if all pass)
  ↓
PolicyEngine.evaluate(run) → NOW has task_category context
  ↓
resolve_route_for_category() → Pareto-optimized route
  ↓
Dispatch → Execution → register_end() → CostAggregator.add_to_category()

CRITICAL PATH:
config.py → routing/task_router.py → cli_impl.py → execution.py → governance/cost.py
          ↑                          ↑             ↑
        (settings)            (integration)   (data capture)

MONITORING (SLOs):
- Routing latency: < 100ms (p99)
- Budget accuracy: < 10% error (estimate vs actual)
- Constraint violation rate: < 1% (false positives)
- Fallback frequency: < 5% for HIGH_COMPLEX tasks

RISKY SPOTS:
1. Concurrent cost tracking (file lock needed for thread safety)
2. Policy ordering (TaskRouter runs before PolicyEngine)
3. Classifier accuracy (token estimation can be off by 2–3x)
4. Config parsing (JSON can fail silently if malformed)
5. Fallback chain unbounding (limit to 10 entries)

ROLLBACK STRATEGY:
- Set THGENT_ROUTING_ENABLED=false → skip classification
- Set THGENT_ROUTING_CONSTRAINTS_ENABLED=false → violations logged but not enforced
- Set THGENT_COST_TRACKING_ENABLED=false → disable cost enforcement
- Restore from backup: cp run_registry.jsonl.backup run_registry.jsonl
- Git revert if needed

TESTING PYRAMID:
